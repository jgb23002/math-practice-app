# Phase 16 accessibility audit

Scope: Section 14 of `Specification.md` and Phase 16 of `TODO.md`. This records implementation and verification, not a full WCAG conformance certification. Phase 17 has not been started.

## Behavior and implementation

| Area                   | Implementation and checks                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keyboard controls      | Native links, buttons, checkboxes, and radio groups retain browser keyboard behavior. Tab reaches enabled controls; radio groups use Tab to enter and arrow keys to select. Enter and Space activate buttons. Existing skip navigation and route/question/reveal focus management are retained.                                                                                                                                                            |
| Answer shortcuts       | With focus inside the question card, 1–4 select and focus the corresponding displayed choice, including zero. Choices show their number and expose `aria-keyshortcuts`. No shortcut flips the card or records a result. Revealed cards ignore shortcuts.                                                                                                                                                                                                   |
| Safe typing            | Shortcuts ignore inputs, textareas, selects, editable ancestors, editable ARIA widgets, modifier keys, held keys, composition input, and previously handled events. There is no document-wide shortcut listener.                                                                                                                                                                                                                                           |
| Focus visibility       | Global focus indicators also apply to the main-content skip target. Answer buttons retain their dedicated outline; setup and settings controls highlight their containing label. All enabled tab stops checked in Chrome had visible outlines. Button backgrounds switch immediately on enablement to avoid a low-contrast intermediate frame.                                                                                                             |
| Labels and semantics   | Existing landmarks, headings, fieldsets, legends, native controls, and definition lists are preserved. All inspected Chrome accessibility-tree controls have names. Icons are decorative and accompany named actions; there are no unnamed icon-only buttons.                                                                                                                                                                                              |
| Questions and progress | A persistent polite, atomic live region announces question number, fixed total or continuous mode, and arithmetic using explicit words such as “divided by.” The answer group references that question description and keyboard instructions. Existing session totals remain a polite, atomic live region. Fixed-session progress exposes minimum, maximum, current value, and question-position text; mastery progress retains its labels and value text. |
| Reveals                | A separate status region stays outside both hidden/inert faces. It starts empty and announces the question, correct answer, selected answer, and self-report instructions after reveal, including when explanations are disabled. The hidden face's controls are disabled and absent from the accessibility tree. Selecting or revealing still never records a result.                                                                                     |
| Motion                 | The existing live `prefers-reduced-motion` subscription and global CSS override are retained. Either reduced motion or the application's Card animation setting disables the flip and arrival animations. Static cards still reveal the answer, move focus, and announce it.                                                                                                                                                                               |
| Non-color cues         | Answers say “Selected” with a checkmark and expose pressed state. Setup choices retain native checked indicators and selection text. Statistics filters now show a checkmark, and current navigation is underlined. Correct/selected answers, self-report results, and mastery states have text labels.                                                                                                                                                    |
| Enlarged content       | The root font now follows the browser's default font size. Font-relative breakpoints, wrapping navigation/buttons, adaptable statistics grids, and stacked narrow cards prevent clipped content. Numeric answers stay together on one line.                                                                                                                                                                                                                |

Character-only shortcuts are limited to the focused component, following the [W3C explanation of character-key shortcuts](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html).

## Automated and browser verification

Run the project checks:

```sh
npm test
npm run lint
npm run format:check
npm run build
```

The full suite passes 1,044 tests in 47 files. The 40 new tests check shortcut positions, zero, changing an answer, reveal locking, explicit self-reporting, external text entry, all operation announcements, persistent question announcements, accessible descriptions, restored reveals, continuous progress, and animation-disabled reveals. Shortcut utility tests cover editable ancestors, native form controls, ARIA editing widgets, modifiers, key repeat, composition, and handled events. Existing tests also cover native keyboard activation, motion preference changes, listener cleanup, settings, navigation, progress, and duplicate-result prevention. The statistics filter test now checks its visible non-color cue.

A local Chrome DevTools Protocol audit exercised Home, Setup, Settings, Statistics, the fallback page, both card faces, subsequent questions, and Summary, using populated mistake/session history. Earlier checks also covered empty statistics. The browser checks used real keyboard events, the accessibility tree, computed styles, rendered text colors/backgrounds, and page/element overflow measurements.

| Browser configuration                                     | Result                                                                                                                                               |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1,280px window, 100% zoom, 16px default font              | Passed keyboard reachability, visible focus, labels, text contrast, and layout checks.                                                               |
| 1,280px window, native 200% browser zoom                  | Passed; effective CSS viewport was 640px and device pixel ratio was 2. This used Chrome's actual zoom preference, not a CSS transform or pinch zoom. |
| 1,280px window, 32px default font                         | Passed; the application's root text increased from 18px to 36px.                                                                                     |
| 390px and 320px viewports, 32px default font              | Passed without page or content overflow.                                                                                                             |
| 320px viewport, 16px default font                         | Passed without page or content overflow.                                                                                                             |
| Both animation settings × both reduced-motion preferences | All four combinations passed; disabling either source removed card motion and preserved reveal/recording behavior.                                   |

The lowest measured contrast for the checked visible, enabled text was approximately 4.53:1. The checks applied the [W3C text-contrast thresholds](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 4.5:1 for ordinary text and 3:1 for large text. Decorative artwork and inactive controls were excluded. Computed-color checks supplement visual inspection; they do not establish conformance for every browser or user color scheme.

The [W3C resize-text guidance](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) informed the zoom and default-font checks. Operating-system font scaling is a separate manual check below; the corresponding TODO remains unchecked.

## Manual verification still required

1. **Screen-reader speech:** Use VoiceOver with Safari and NVDA with Firefox or Chrome. Start a session, enter the answer group, select with 1–4, flip, self-report, and continue. Check operation pronunciation, question/progress announcements, correct and selected answers, and the absence of unrevealed answers. Check that focus changes and live regions do not cause confusing repetition or cut-off speech. Repeat with explanations and animation disabled, restored revealed cards, and continuous practice. DOM assertions and an accessibility tree cannot verify the actual spoken experience.
2. **Operating-system text size:** Enable the platform's larger text/display scaling, then repeat Setup, a full session, Summary, Settings, and populated Statistics. Check labels, navigation, focus visibility, reading order, and clipping. Enlarged browser default fonts were tested; native OS font scaling was not. Complete the final Phase 16 TODO checkbox after this check passes.
3. **Browser/platform differences:** Repeat keyboard navigation, radio arrow keys, skip navigation, native Reset/Clear All confirmation dialogs, and 200% zoom in the target Safari/Firefox/Chrome versions. Check focus after cancelling confirmations, returning home, and starting another session. Restore zoom and font preferences afterward.
4. **Visual and motion experience:** Inspect focus visibility against actual backgrounds, selected/results text without relying on color, and reduced-motion behavior with the real OS setting. Check readability and spacing at 200% zoom and enlarged fonts with a person using those settings; numerical overflow checks cannot judge whether a layout is comfortable to read.

For a manual walkthrough, run `npm run dev`, open the displayed local URL, use only Tab/Shift+Tab, arrows, Space, Enter, and 1–4, and finish a five-question session. Use the same routes and data states for the zoom, font, screen-reader, and OS checks.
